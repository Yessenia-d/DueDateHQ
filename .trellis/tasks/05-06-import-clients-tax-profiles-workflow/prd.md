# Implement Import clients and tax profiles workflow

## Goal

Make Import a first-class workflow for starting a new DueDateHQ workspace. A CPA with no clients should be guided to import clients and tax profiles from CSV, create or match Client Relationships, create Filing Profiles, and generate Deadline Tasks from Verified Tax Rules.

## What I Already Know

- The user approved the product decision that CSV import is the default first step for an empty workspace.
- Import should be a sidebar entry named `Import`.
- The `/import` page title should be `Import clients and tax profiles`.
- One CSV batch can contain many clients and many filing profiles.
- Each CSV row represents a Filing Profile, not just a contact.
- Multiple rows can share one Client Relationship.
- DueDateHQ internal `clientRelationshipId` must always be generated by DueDateHQ or selected from existing records, never imported from CSV as a primary key.
- CSV `source_client_id` is an external system id used only for matching, duplicate detection, audit, and future sync.
- Manual client creation remains available, but it is not the required first step before import.

## Requirements

### Information Architecture

- Add `Import` as a first-level sidebar navigation entry.
- Keep `/import` as the route for this workflow.
- Update `/import` page heading to `Import clients and tax profiles`.
- Dashboard empty state must send new users to `/import` as the primary CTA.
- Clients page header and empty state must offer `Import clients and tax profiles`; `New client relationship` should be secondary.
- Tax Work empty state must offer `/import` and manual client creation; it must not say clients must be added before importing.
- Existing client context should use the narrower label `Import tax info for this client`.

### Import Modes

- Add a compact mode selector on `/import`.
- Default mode: `Clients and tax profiles`.
  - Allows empty workspace imports.
  - Explains that each row describes one filing profile and can create or match a client.
- Context mode: `Tax info for selected clients`.
  - Shown/selected when `clientIds` search params are present.
  - Explains that the import applies to selected existing clients.

### CSV Model

- Support a standard DueDateHQ CSV template with these canonical fields:
  - Required: `client_name`, `entity_type`.
  - Recommended: `source_client_id`, `states`, `fiscal_year_type`, `ein`, `ssn_last4`, `source_row_id`, `filing_profile_name`.
- `entity_type` must map to: `individual`, `sole_prop`, `s_corp`, `c_corp`, `partnership`, `llc`, `trust_estate`, `nonprofit`, `other`, while retaining existing alias support such as `1040`, `1120S`, `1065`, and `LLC`.
- `states` should accept one or more states such as `CA` or `CA;NY`. Existing single-state behavior may be extended, but if multi-state support is too broad for the current architecture, implement the minimum safe support needed by tests and keep missing/ambiguous states in review.
- Missing `entity_type` must put the row in `Needs review` and must not generate verified tasks.
- Missing `states` should not block profile commit, but state-level verified tasks must not be generated from missing state data.
- CSV must not directly create verified deadlines. Verified Deadline Tasks can only come from Verified Tax Rules.

### Client Matching and IDs

- Add canonical import fields:
  - `sourceClientId`
  - `filingProfileName`
- Add optional external source id storage on Client Relationship:
  - `sourceClientId: string | null`
- Deduplicate non-empty `firmId + sourceSystem + sourceClientId` through a database uniqueness constraint or equivalent application-level guard.
- During commit:
  - Reuse an existing Client Relationship when source-system and source-client-id match.
  - Within the same CSV batch, reuse one Client Relationship for multiple rows with the same source client id.
  - Fall back to existing duplicate review behavior when only weak name matching is available.
  - Create a new Client Relationship only when no existing or same-batch match applies.
- Filing Profile display name should use `filingProfileName` when present; otherwise fall back to `clientName`.

### Preview and Commit Summary

- Import preview should surface counts for:
  - new client relationships
  - matched client relationships
  - filing profiles
  - tasks to generate when safely knowable
  - needs review rows
- Commit summary should clearly report:
  - created client relationships
  - matched or updated client relationships where available
  - created filing profiles
  - generated verified deadline tasks
  - rows still needing review

## Acceptance Criteria

- [ ] Sidebar includes first-level `Import` navigation to `/import`.
- [ ] `/import` title is `Import clients and tax profiles`.
- [ ] Empty Dashboard, Clients, and Tax Work states guide users to `/import` without requiring manual client creation first.
- [ ] Standard CSV with multiple clients imports into multiple Client Relationships, Filing Profiles, and verified-rule tasks.
- [ ] Standard CSV with repeated `source_client_id` creates one Client Relationship and multiple Filing Profiles.
- [ ] Re-import with the same `source_system + source_client_id` reuses an existing Client Relationship.
- [ ] A row missing `entity_type` remains in review and does not generate verified tasks.
- [ ] A row missing `states` can commit a profile but does not generate state-level verified tasks from missing state data.
- [ ] Typecheck, lint, and relevant tests pass.

## Out of Scope

- Direct TaxDome, Karbon, Drake, or QuickBooks API sync.
- Arbitrary CSV inference beyond DueDateHQ standard template and existing source-system adapters.
- Email and phone import as core fields, unless already supported and low risk.
- Two-way external system synchronization.
