跳到用户旅程

DueDateHQ Product Journey

从 client list 到可信 due date dashboard

这份用户旅程地图用 CPA 的视角说明 DueDateHQ Beta 应该让用户看到什么、做什么、相信什么。它不是 PRD 的替代品，而是把产品意图连成一条可打开、可评审的端到端体验。

30 秒 登录后看到本周所有需要处理的 deadline。
5 分钟 完成 weekly triage，替代 30-45 分钟表格/日历交叉检查。
30 clients TaxDome 等 CSV import 目标 P95 不超过 30 分钟。
知道哪个 deadline due、为什么 due，以及 source 是否 Verified。 DueDateHQ 的核心不是堆更多 due dates，而是把 official source、tax rule version、verification status 和 manual fallback 清楚展示出来。只有 Verified tax rule 可以生成 official system-generated deadline task。

01 · FLOW OVERVIEW

CPA 期望的一条直线

用户不应该先读 tax rule library、API 或技术文档。产品第一感知应该是：我把 client 放进来，系统告诉我哪些 due date 可信、哪些需要我或 DueDateHQ 处理，然后给我一个可执行的本周 dashboard。

1

登录与初始化

CPA 创建账号，进入单用户 workspace，看到 CSV import 和 manual entry 入口。

2

client 进入系统

从 TaxDome、Drake、Karbon、QuickBooks 做 CSV import，或通过 manual entry 创建 client。

3

field mapping 与 duplicate detection review

系统自动识别 client name、EIN、state、entity type，不确定行进入 review。

4

obligation mapping

client profile 匹配 50-state obligation library，区分 Verified、Needs review、Unsupported。

5

生成 due date calendar

只有 Verified tax rule 生成 official full-year tasks，manual entry 的 due date 清楚标注。

6

weekly triage

默认看到 Due today、This week、This month、Long range 和 dashboard urgency surface。

7

Evidence 与 Source changed

每个 official task 可打开 Evidence，Source changed 进入 verification queue。

8

manual entry 兜底

特殊 due date 可以作为 User provided task 出现，并可请求 review。

9

progress 与 export

task status、feature progress、current view export 支撑 review 和 workload sharing。

10

Beta 边界

不做 desktop database、复杂 reports、external email/SMS/calendar reminders 和 unreviewed automatic interpretation。

每一步用户看到什么

02

CSV import clients，或 manual entry 创建 client

DueDateHQ 需要把 CPA 现有 client data 变成统一的 tax profile：client name、EIN、entity type、jurisdiction/state、county、fiscal year 和 notes。批量 migration 走 CSV import，edge cases 走 manual entry。

用户目标

不用从零敲 30 个 clients，也不因为几行有问题卡住整个 CSV import。

关键动作

选择 TaxDome、Drake、Karbon 或 QuickBooks，上传 CSV，review field mapping 和 duplicate detection。

系统反馈

展示 header detection、mapping confidence、accepted rows、review rows、duplicate candidates。

CPA 看到

大部分 clients 已可提交，不确定 clients 被隔离到 review，而不是静默丢弃。

03

CSV import 成功不等于 due date 都已确认。系统会用 client 的 entity type、jurisdiction、tax type 和 fiscal year 匹配 obligation library，并把 known obligation 和 verified schedulable tax rule 分开。

用户目标

知道哪些 clients 已经能生成 official tasks，哪些只是 coverage gap 或 Needs review。

关键动作

查看 import summary，打开 coverage detail，对 gap 请求 coverage。

系统反馈

按 Verified、Needs review、Source changed、Unsupported 和 User provided 分类展示。

CPA 看到

透明的 coverage status，而不是把所有 known obligation 都伪装成 official due date。

用户目标

关键动作

提交 CSV import，查看 created clients、generated tasks、Needs review 和 Unsupported 汇总。

系统反馈

生成 official tasks、显示 extension due date Evidence、保留 Unsupported obligation 的 coverage 入口。

06

CPA 对某个 date 不放心时，不需要离开产品去猜。official task 可以打开 Evidence，看到 source URL、date calculation、last checked、last verified、tax rule version 和 audit trail。

用户目标

理解这个 due date 为什么可信，以及 Source changed 后产品如何保护她。

关键动作

打开 Evidence drawer，报告问题，请求 re-verification，或查看 Source changed 警告。

系统反馈

关键动作

系统反馈

03 · TRUST STATES

Trust status 决定 due date 能不能变成 official task

这是 DueDateHQ 区别于桌面 bundled due-date 数据的核心。status 不是内部技术字段，而是 CPA 在 dashboard、coverage matrix 和 Evidence 中必须看得懂的产品语言。

Status CPA 看到的含义 是否生成 official task Next action
Verified official source、date calculation、applicability 和 reviewer action 都已完成 review，source 未变化。 可以生成 official task。 打开 Evidence，查看 source、tax rule version、last checked 和 last verified。
Needs review candidate tax rule 存在，但 review 未完成或 source 不清楚。 不可以。 进入 verification queue；user 可请求 coverage 或等待 review。
Source changed 之前 Verified 的 official source 发生 change，需要 re-review。 不生成 new official task。 受影响 tax rule 进入 Source changed queue，review approved 后才 publish new version。
Unsupported DueDateHQ 知道这项 obligation exists，但 Beta 暂不能安全生成 deadline task。 不可以。 在 coverage matrix 中透明展示，可请求 coverage。
User provided CPA manual entry 的 due date，可作为 task 出现，但不是 DueDateHQ Verified due date。 不是 official system task。 可继续处理，或发起 DueDateHQ verification request。

05 · BETA BOUNDARIES

Beta 的承诺和不承诺

用户旅程必须诚实。DueDateHQ Beta 可以清楚展示 coverage gaps 和 User provided due date，但不能暗示 unreviewed tax rule 等同于 official due date。

Beta 必须覆盖

  • 邮箱密码登录。
  • 四类 CSV import source。
  • manual entry clients 和 due dates。
  • Verified rules 生成 official tasks。
  • weekly triage、filters、sorting、status updates。
  • Evidence、coverage、source monitoring 和 verification queue。

Beta 先不承诺

  • production-grade tax liability guarantee。
  • 未经 human review 的 automatic tax rule interpretation 或 rule publish。
  • 完整 city/county/industry 自动化。
  • OAuth、MFA、组织、邀请和复杂权限。
  • 外部 email、SMS、calendar reminders。

明确不是桌面克隆

  • 不暴露本地数据库、备份、优化和网络用户维护。
  • 不做 Crystal Reports-style builder。
  • 不做 mail merge、labels、extension form printing。
  • 不做 arbitrary field renaming 和复杂 saved-view 膨胀。
  • official recurring deadlines 不需要 manual rollover。

产品理解的最终检查

看完这份旅程后，评审者应该能说清：DueDateHQ 如何从 client import 开始，生成可信 due date calendar，帮助 CPA 完成 weekly triage，在 Source changed 时暂停 trust，并用 manual entry due date 兜底但不混淆 official verification status。
